# Literal implementation decisions and unfinished gates

METHOD.md is unchanged. No confirmation outcomes or simulated outcomes have been inspected. These entries are outcome-blind implementation disclosures, not a waiver of any acceptance rule.

1. **Commit barriers applied literally.** METHOD requires committed support before synthetic results, and a committed machine-readable scenario manifest plus executable generator before the first synthetic outcome. The owner says “You cannot write to `.git`; Claude commits.” The schedule-only support can be prepared, but simulations must stop at those unmet prerequisites. Statistical gates are BLOCKED / NOT RUN, never failed estimates or completed passes. `gate.py` is currently the prerequisite checker/report writer; the complete scenario generator and Monte Carlo runner remain to be implemented and committed.
2. **Source row ID formatting.** Use the pilot's one-based nine-digit zero-padded ordinal: `YYYY-MM:RRRRRRRRR`. This instantiates METHOD's unspecified ordinal formatting and makes the LF-terminated list's lexical order identical to numeric source order. Natural-key collisions are retained and separately reported; source IDs, not flight numbers, identify rows.
3. **Strict schedule integer parsing.** Only ASCII decimal digit strings, after whitespace stripping, parse as integer HHMM. A fractional string such as `12.5` is invalid; no rounding. `2400` alone normalizes to next-day midnight. Invalid airport/time keys use FlightDate weeks nationally. Source-year boundary weeks remain separate.
4. **Official domestic/territory metadata.** Freeze BTS's Airport ID lookup and aviation state/region lookup. US regions are that lookup's non-Canadian entries, including PR, VI and TT (US Pacific possessions). Airport identity is never consolidated. Official source documentation establishes domestic nonstop scope; an unknown airport ID stays in the national source population as an invalid matching key. An officially identified foreign endpoint excludes that candidate service. No outcome-dependent exclusion is possible.
5. **CSV projection and process denial.** Arrow CSV `ConvertOptions(include_columns=FIELDS, column_types=string)` materializes only Year, Month, FlightDate, the reporting/DOT/IATA identity fields, reporting flight number, two Airport IDs and CRSDepTime. All mixed-file bytes are scanned for CSV framing, but nonselected fields are not inferred, converted, materialized, logged or exposed. Raw ZIPs are hashed as opaque bytes. The workspace resets raw-directory mode 000 to 0700 between tool calls, and nested `sandbox-exec` is rejected with `sandbox_apply: Operation not permitted`. Gate/verification Python processes therefore install and test an audit hook rejecting raw opens/traversal and network connections; only read-only `git show` subprocesses are allowed. This is a process safeguard, not an OS isolation claim. No simulation runner has been executed; stronger native-library containment must be addressed before implementing one if it can bypass Python open auditing.
6. **Official lookup encoding and source access.** The airport lookup contains CP1252 names; metadata decoding uses that encoding without changing the privately saved byte hash. Local historical ATCR PDF and BTS policy downloads return HTTP 403. Failures are recorded with URLs/status/date and no invented hash. ATCR explanatory notes (February 2016, printed page 3) were read through the web tool; saved BTS dictionary bytes and the registered rules resolve the field mapping/status/normalization before schedule ingestion. There is no claim of a locally sealed ATCR PDF. Exact reporting-carrier raw redistribution terms remain unresolved; raw/row-level release is disallowed under METHOD's explicit fallback.
7. **Monthly support mass and component order.** Pair-cell weight mass is reported by normalized matching month, with source-month schedule/shared-record counts separately reported and source-month IDs preserved in pair-membership.parquet. Component order is sorted pair, A/B, G/D, primary/low/high. Duplicate components are retained, and reverse directions are exact negations. The omission airport set is hashed in numeric order; its count-descending selection order is separately reported.
8. **Sensitivities remain descriptive.** Freeze the original roster for one-/four-hour windows, equal/harmonic weights, source years, equal-year A, five airport omissions and reciprocal nearest departures. Nearest departures can cross bands and use one-pass mutual choices, with numeric month/ordinal tie-breaking. No alternative support minima, weak-pair removal, resampler change, larger alternative or reduced simulation count is introduced.
